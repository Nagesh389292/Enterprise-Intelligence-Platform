# Data Ingestion Framework Architecture
### NexaCore Enterprise Intelligence Platform

---

## 1. Medallion Layer Architectural Boundaries

The platform organizes data processing into four distinct Medallion storage tiers:

```text
 ┌──────────────────┐
 │   RAW LANDING    │  Parquet/CSV raw files generated by enterprise_data_generator
 └────────┬─────────┘  Location: data/raw/generated/*.parquet
          │
          ▼
 ┌──────────────────┐
 │  BRONZE LAYER    │  Raw immutable append-only archive with ingestion metadata
 └────────┬─────────┘  Location: data/bronze/ + audit.pipeline_execution_logs
          │
          ▼
 ┌──────────────────┐
 │ VALIDATION GATE  │  Data contract validation (Pydantic / Great Expectations)
 └────┬────────┬────┘
      │        │
 Valid│        │Invalid
      ▼        ▼
 ┌─────────┐ ┌────────────┐
 │ SILVER  │ │ QUARANTINE │  Conformed conformed entities vs trapped defect records
 └────┬────┘ └────────────┘  Location: source.* vs audit.quarantine_records
      │
      ▼
 ┌─────────┐
 │  GOLD   │  Star-schema analytical dimensions & facts
 └────┬────┘  Location: analytics.*
      │
      ▼
 ┌──────────┐
 │ POSTGRES │  Production Data Warehouse & Serving Layer
 └──────────┘  Port: 5433 (Host) / 5432 (Container)
```

---

## 2. Layer Characteristics & Responsibilities

| Medallion Layer | Schema / Location | Primary Purpose | Storage Format | Mutability |
| :--- | :--- | :--- | :--- | :--- |
| **Raw Landing** | `data/raw/generated/` | Initial landing directory for raw source files | Parquet / CSV | Transient / Overwritten |
| **Bronze Layer** | `data/bronze/` | Immutable historical archive tagged with batch metadata | Partitioned Parquet | Immutable Append-Only |
| **Silver Layer** | `source.*` schema | Cleaned, conformed 3NF entity tables in PostgreSQL | PostgreSQL Tables | Upsert / Mutable |
| **Gold Layer** | `analytics.*` schema | Dimensional star-schema facts and dimensions | PostgreSQL Tables | Read-Optimized |
| **Quarantine** | `audit.quarantine_records` | Isolated storage for contract-violating records | PostgreSQL Table | Log Append-Only |

## 3. Technology Evaluation: Current vs Future

| Processing Stage | Current Stack (Development / Prototyping) | Future Scale Stack (Production / Cloud) | Rationale for Evolution |
| :--- | :--- | :--- | :--- |
| **File Parsing & I/O** | Python 3.13, PyArrow, Pandas | PySpark (Apache Beam on Dataflow) | Pandas handles local dev (< 5 GB); PySpark distributed engine handles 20M+ scale telemetry |
| **Data Validation** | Pydantic v2 & Custom Checkers | Great Expectations & Soda Core | Automated data contract enforcement at scale |
| **Database Driver** | SQLAlchemy 2.0 & `psycopg2-binary` | PySpark JDBC / psycopg3 connection pool | Fast batch loading into PostgreSQL |
| **Transformations** | Raw SQL / Python scripts | dbt Core (`dbt-postgres`) | Modular SQL dependency DAGs and data documentation |
| **Orchestration** | Python CLI / Local Cron | Apache Airflow (Cloud Composer) | Scheduled DAG orchestration, SLA alerts, dependency management |
